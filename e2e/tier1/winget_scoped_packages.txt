# Every winget package mapped in setup/ansible/vars/Windows.yaml whose newest manifest in
# microsoft/winget-pkgs leaves the choice of installer to a scope: one that offers a user-scope
# installer, or more than one distinct scope, counting an installer that declares none as "none".
# Each one must pin a scope in its mapping, and the scope it pins must be one its manifest can
# serve. A mapping that pins a scope is listed here as well, even when its manifest offers no
# choice, because this list is also the evidence for its installer type.
#
# Format: <package id> <scopes the newest manifest declares, sorted, comma separated> <machine type>
#
# The machine type is the installer type winget selects for --scope machine, or "-" when no
# installer in the manifest serves a machine install. Every machine pin carries it as installer_type
# in its mapping, and setup/windows/WindowsSoftware.ps1 runs winget elevated when it is msix,
# msstore, portable or font, the types winget refuses to install machine-wide from a process that
# is not elevated.
#
# tier1/winget_scope_pins.sh enforces this offline. tier2/resolve_packages.sh reads every winget
# manifest again and fails when the live answer differs from this file, printing the lines to put
# here instead, because a manifest gains or loses a scope or an installer with no warning to anybody.
#
# Read from winget-pkgs on 2026-10-11, and every machine type agreed with
# `winget show --exact --id <id> --scope machine` on winget v1.29.380 the same day. GitHub sweep run
